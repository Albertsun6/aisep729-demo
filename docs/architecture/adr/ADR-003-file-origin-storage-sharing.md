# ADR-003：file:// 下 localStorage 为全局共享 origin —— 存储键必须带独特命名空间

- 状态：proposed（门禁②批准后翻 accepted）
- 日期：2026-07-31
- 关联：ADR-001 · SPEC-2 · PRD NFR-4 · 异构评审单点风险（file:// 持久化假设未验证）

## 背景与驱动力

异构评审（跨模型 lens）指出：本设计的地基假设——"双击 `file://` 打开时 localStorage 能长期稳定持久化"——**从未被验证**，且移动/重命名文件可能进入新存储区。同模型预审未发现此风险（共享盲区）。

**实测结论**（Chrome DevTools，2026-07-31）：

| 场景 | 结果 |
|---|---|
| 首次写入 → 立即读回 | ✅ OK |
| 刷新页面后读取 | ✅ 读到上次写入（持久化成立） |
| **改文件名后读取** | ✅ **仍读到**——数据不随文件名走 |
| `location.origin` | **`file://`**（不含路径，非 opaque origin） |
| localStorage 内的键 | 含 `gambleTrackerV1`——**本机另一个无关本地网页写的** |

→ **Chrome 下所有 `file://` 页面共享同一个 localStorage**。评审担心的"丢数据"不成立；但暴露了它没预料到的方向：**同机任意本地 HTML 可读写我们的数据，且键名冲突是真实风险**（本机已存在同类应用的键）。

## 备选方案

### 选项 A：普通键名 `winLossLog.v1`（原设计）
- 优点：简短
- 代价：与本机其它 file:// 页面**同一命名空间**；实测已存在 `gambleTrackerV1` 这类同域键，撞名即互相污染

### 选项 B：带独特命名空间前缀 `e2e.winLossLog.v1`
- 优点：撞名概率极低；一眼看出归属；零成本
- 代价：键名略长（无实质代价）

### 选项 C：改用 IndexedDB 求隔离
- 优点：数据库名隔离更清晰
- 代价：**同样是 file:// origin 共享**，隔离性没有实质提升；且引入 ADR-001 已否决的异步复杂度——**用更大代价换不到隔离**

## 决定

选 B：存储键改为 **`e2e.winLossLog.v1`**。同时：
1. **PRD NFR-4 表述修正**：从"数据不出本机"改为"**数据不出本机；但同机其它本地网页可读——`file://` 共享 origin 是浏览器行为，非本应用可控**"
2. 读取时对**非本命名空间的键一律不碰**（避免误伤 `gambleTrackerV1` 等他人数据）
3. **Safari 未验证**：本次仅 Chrome 实测；Safari 对 file:// 存储更严格，列入门禁④ 人工 checklist，未验证前不得声称"跨浏览器可用"

## 后果

- ✅ 地基假设已从"未验证"变成"Chrome 实测确证 + 边界清楚"
- ✅ 键冲突风险出清（前缀 + 只碰自己命名空间）
- ⚠️ **隐私边界如实降级**：无法阻止同机其它本地页面读取——这是 file:// 的固有属性，须在手册与 FAQ 写明
- ⚠️ Safari 行为未知，门禁④前必须人工验 → **已于 2026-07-31 补验，见下方追加记录**
- 可复议条件：若未来改为 http(s) 部署，origin 隔离自然成立，本 ADR 的约束可放宽（新 ADR）

## 追加记录：Safari 补验（2026-07-31，门禁④）

> ADR 不可变只追加（宪法 C5）。原文一字不改，此处如实追加实测与**对原判断的修正**。

用 `osascript` 驱动 Safari（用户开启「允许 Apple 事件中的 JavaScript」后）实跑 C1-C11 + 两条关键断言。

| # | 断言 | 判定 | 证据 |
|---|---|---|---|
| S-1 | Safari 对 `file://` 存储更严格，**可能拒绝 localStorage**（原文「决定」第 3 条的预设） | ❌ **REFUTED** | `localStorage.setItem` 成功，`LS_可写: true`，无异常抛出。写入一笔 `+777` 后 `err` 为空（未走"未能保存"降级分支） |
| S-2 | 刷新后数据持久化 | ✅ CONFIRMED | 刷新后流水 `['2026-07-31　Safari测试+777']`，原始存储 `[{"schemaVersion":1,…,"amount":777}]` |
| S-3 | **同机其它本地页可读同一 localStorage**（本 ADR 的核心隐私结论） | ✅ **CONFIRMED，Safari 与 Chrome 一致** | 另建 `/tmp/other-page.html`，在其中读 `e2e.winLossLog.v1` → **完整读到那条赌博记录**；`localStorage.length` 为 2（自己的键 + 我们的键） |
| S-4 | C1-C11 功能项 | ✅ 全过 | 三层加载 ✓ / 三屏切换且唯一可见 ✓ / 非法金额全拒 ✓ / 上限拦截 ✓ / 缺日期提示"请选日期" ✓ / 汇总 `+777` `共 1 笔` ✓ / 隐私声明 ✓ / 无横向溢出 ✓ / `协议: file:` `UA: Safari` |

**对原判断的修正**：原文「决定」第 3 条写"Safari 对 file:// 存储更严格"——这个方向**猜错了**。
Safari 在 `file://` 下与 Chrome 同样宽松：既允许 localStorage，也**同样共享 origin**。

**因此隐私结论不但没有放松，反而更强**：跨浏览器一致地成立——
「同机任意本地 HTML 页面都能读到本应用的数据」不是 Chrome 的特例，是 `file://` 的固有属性。
手册与 FAQ 的措辞按此加强，**不得**写成"某些浏览器下可能被读取"。

**解除的限制**：ADR-003 原定"未验证前不得声称跨浏览器可用"——该限制**现已解除**，
Chrome + Safari 双浏览器实测通过，可声称"macOS 上 Chrome 与 Safari 均实测可用"。
**仍不得**声称 Windows / Linux / 移动端可用（未测，见 ADR-007 仅 macOS 实测）。

**留痕**：本次实测在 Safari 的 localStorage 里产生的测试数据（`Safari测试 +777` 记录、
`safariOtherPageKey`）已清理，实测后 `localStorage.length === 0`。
